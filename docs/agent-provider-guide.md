# AI Agent 연결 안내

앱의 대화 탭은 Codex CLI로 단일 질문·답변을 제공합니다. 메모·근무시간·캐릭터는 AI 연결 없이 독립적으로 동작합니다. 대화로 앱 데이터를 조작하거나 이전 대화를 장기 저장하는 기능은 아직 없습니다.

## 두 가지 AI 사용 흐름

1. **프로젝트 수정:** 사용자가 프로젝트 폴더에서 Codex·Claude Code 등을 실행해 캐릭터나 소스를 수정합니다. [캐릭터 제작 가이드](character-guide.md)를 따릅니다.
2. **앱에서 질문:** 대화 탭에 입력한 질문을 Codex CLI에 전달하고, 답변을 패널과 캐릭터 말풍선에 표시합니다.

프로젝트를 수정하는 Agent와 앱에서 질문에 답하는 Agent는 서로 다른 책임입니다. 캐릭터를 수정하기 위해 앱에 AI API 키를 저장할 필요는 없습니다.

## 구현 구조

```text
대화 UI
  → preload의 제한된 IPC
    → ChatService: 연결·요청·취소 상태
      → AgentProvider 공통 계약
        → CodexProvider: 실행 파일·CLI 인자·출력 변환
          → process: stdin·출력 제한·시간 제한·종료
```

`src/main/ai/provider.ts`의 `AgentProvider`는 연결 확인과 `{ question, signal }` 질문을 받아 일반 텍스트 답변 또는 분류된 오류를 반환합니다. `src/shared/chat.ts`는 CLI와 무관한 상태 형식과 질문·답변 길이 제한을 정의합니다. UI나 메모·근무시간 모듈은 CLI 플래그와 JSONL 형식을 알지 못합니다.

현재 기본 구현은 Codex 하나입니다. `DesktopController`의 `agentProvider` 옵션으로 다른 구현을 주입할 수 있으나 사용자가 연결 대상을 선택하는 UI는 아직 없습니다.

## Codex 준비와 실행

- Codex CLI `0.154.0` 이상을 설치하고 터미널에서 `codex login`으로 로그인합니다. [설치 안내](https://developers.openai.com/codex/cli), [비대화형 실행 안내](https://developers.openai.com/codex/noninteractive)를 참고하세요.
- **대화** 탭을 처음 열 때 버전·필수 실행 옵션·로그인 상태를 확인합니다. **다시 확인**으로 재시도합니다. 연결 확인에는 모델 요청이 없습니다.
- PATH, Homebrew, `~/.local/bin`과 nvm에서 실행 파일을 찾습니다. 필요하면 앱 실행 환경에 `DESKMATE_CODEX_PATH`를 절대경로로 지정합니다. 설정과 인증 파일은 공유 소스에 포함하지 않습니다.
- 앱은 CLI의 기존 인증을 재사용하고 인증 파일 내용을 읽거나 복사하지 않습니다. 인증 상태 출력과 원문 진단은 고정 안내로 바꾸어 UI에 전달합니다.
- 질문마다 빈 임시 작업 폴더에서 `codex exec`를 실행합니다. 질문은 셸 명령 문자열이나 인자가 아닌 stdin으로 전달합니다. 실행 파일과 인자를 분리하고 `shell: false`로 실행합니다.
- `--json`, `--ephemeral`, `--ignore-user-config`, `--sandbox read-only`와 승인 요청 금지 옵션을 사용합니다. 셸·브라우저·연결 앱·플러그인·훅·기억 등의 도구를 비활성화하고 프로젝트 안내를 읽지 않도록 설정합니다. 기존 실행 규칙은 유지합니다.
- 모델 이름은 고정하지 않고 CLI 기본값을 사용합니다. 개인 CLI 설정을 불러오지 않으므로 그 파일의 모델·도구 설정도 적용하지 않습니다.

이 연결은 일반 질문·답변 범위입니다. 실시간 날씨·검색이나 로컬 파일 작업은 지원하지 않습니다. 읽기 전용은 CLI의 실행 정책이며 별도의 운영체제 가상 환경을 만드는 기능은 아닙니다. CLI의 인증 캐시와 자체 운영 기록은 CLI 관리 범위입니다. `--ephemeral`은 세션 파일 저장을 생략하는 옵션입니다.

## 요청 수명과 표시

- 질문은 앞뒤 공백을 제외한 1~4,000자이며 한 번에 하나만 실행합니다. 연결 확인과 질문도 서로 겹치지 않습니다.
- 답변을 기다리는 동안 **취소**할 수 있습니다. 취소는 요청 ID를 검사하고 해당 프로세스 그룹을 종료합니다. 취소·종료 후 늦게 도착한 결과는 무시합니다.
- 실행 제한 시간은 연결 검사 명령당 5초, 질문 명령 120초입니다. 질문 실행 전 버전·옵션·인증을 다시 확인합니다. 표준 출력·오류 합계가 제한을 넘으면 종료합니다.
- 답변은 JSONL의 완료된 Agent 메시지만 읽습니다. 추론·도구 실행 내용은 답변에 넣지 않으며, `turn.completed`와 정상 종료가 모두 있어야 성공입니다. 빈 답변·16,000자를 넘는 답변·파싱 실패·비정상 종료는 오류로 표시합니다.
- 마지막 질문·답변만 앱 메모리에 유지합니다. 이전 대화·메모·근무시간은 자동으로 전달하지 않고 앱을 재실행하면 대화는 초기화됩니다.
- 답변은 일반 텍스트로 표시하며 HTML이나 명령으로 실행하지 않습니다. 긴 답변은 패널과 말풍선 안에서 스크롤합니다. 말풍선을 닫아도 패널 답변은 유지합니다.
- 예약 메모 알림은 AI 답변과 미리보기보다 우선합니다. 답변이 대기할 때는 알림을 닫은 뒤 표시하고, 드래그·놓기 중에는 표시를 미룹니다. 새 질문은 이전 답변 말풍선과 대기 답변을 제거합니다.

## 후속 확장

다른 Agent를 연결할 때는 `AgentProvider` 구현과 연결 선택 설정을 추가합니다. 공통 UI나 메모·근무시간 코드에 Agent별 실행 형식을 넣지 않습니다.

“3시 회의 추가해줘” 같은 앱 조작은 후속 범위입니다. 답변 텍스트와 앱 명령을 구분하고, 기존 도메인 검증과 저장 기능을 거쳐 실행해야 합니다. 자유 형식 답변을 바로 명령으로 실행하지 않습니다.

근무시간 조작은 `src/main/domain/worktime.ts`와 `worktime-store.ts`를 재사용합니다. 메모 조작은 `src/main/features/memos.ts`의 `MemoService`를 사용해 날짜 없는 `HH:mm` 입력, 완료 상태, 일회성 예약·확인 상태와 이전 저장 형식의 원본 백업을 유지합니다. Provider가 `memos.json`이나 `worktime.json`을 직접 수정하지 않게 합니다.
