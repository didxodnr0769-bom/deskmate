# AI Agent 연결 안내

0.14.0 소스는 전용 대화 창의 이어지는 질문·답변과 허용된 앱 명령을 제공합니다. AI는 명령을 제안하고 실제 데이터 조회·변경은 앱 main 서비스가 검증·실행합니다. 날짜별 메모·근무·반복 알림은 AI 연결 없이도 동작합니다.

이 문서는 연결 계약과 커스터마이징 기준입니다. 실제 수행한 검증과 남은 점검은 [검증 안내](verification.md)를 참고하세요.

## 두 가지 AI 사용 흐름

1. **프로젝트 수정:** 프로젝트 폴더에서 Codex·Claude Code 등 개인 Agent에 소스·캐릭터·Provider 교체를 요청합니다. 외형 변경은 [캐릭터 가이드](character-guide.md)를 따릅니다.
2. **앱에서 대화:** 현재 질문·실제 대화 이력으로 답변 또는 앱 명령 JSON을 요청하고 앱이 결과를 대화 창·말풍선에 표시합니다.

프로젝트를 수정하는 Agent의 권한과 앱 안에서 대화하는 Provider의 권한은 분리합니다. 개인 Agent 설정·인증·대화 기록은 공유 소스에 넣지 않습니다.

## 공통 Provider 계약

~~~text
대화 UI → 제한된 preload IPC → ChatService
  → AgentProvider.ask({ question, history, appCommands, signal })
    → 답변 또는 앱 명령 envelope 문자열
  → AppCommandService: 명령·대상·값 검증
    → main의 앱 포트 → 기존 도메인·저장 서비스
  → 실제 실행 결과를 대화 이력·말풍선에 표시
~~~

`src/main/ai/provider.ts`의 `AgentProvider`는 `id`, `label`, `checkConnection(signal)`, `ask(...)`를 구현합니다. 입력의 `history`는 이전 `ChatMessage` 목록이고 `signal`은 취소 신호입니다. `appCommands`가 켜져 있으면 아래 JSON envelope로 응답합니다. 연결 상태·오류와 대화 상태는 CLI와 무관한 공통 형식을 사용합니다.

현재 기본 구현은 `CodexProvider`입니다. `DesktopController`의 `agentProvider` 옵션으로 다른 구현을 주입할 수 있습니다. 실행 파일·인자·출력 형식·인증 방식은 어댑터에 두고 공통 UI와 업무 서비스에 Agent별 분기를 퍼뜨리지 않습니다.

## 앱 명령 envelope와 허용 범위

일반 대화·추가 확인은 다음 형식입니다.

~~~json
{ "kind": "reply", "text": "사용자에게 보여줄 답변" }
~~~

앱 조회·변경은 한 요청에 정확히 한 명령을 제안합니다.

~~~json
{
  "kind": "command",
  "command": {
    "name": "memo.add",
    "text": "물 마시기",
    "reminder": { "kind": "after", "minutes": 10 }
  }
}
~~~

| 명령 | 기능 |
| --- | --- |
| `memo.list` | 날짜·검색어·완료 여부로 메모 조회 (날짜 생략은 오늘) |
| `memo.add` | 본문과 선택적인 예약 추가 |
| `memo.update` | 검색어에 맞는 메모의 본문·예약 변경 |
| `memo.complete` | 완료 또는 완료 취소 |
| `work.get`, `work.update` | 적용된 근무 조회·날짜와 출퇴근 시각 변경 |
| `character.walk` | 자율 이동 켜기·끄기 |
| `ui.open` | 대화·근무·메모·캐릭터·앱 설정 화면 열기 |
| `summary.get` | 적용된 근무 현황과 오늘의 남은 메모 요약 |

메모 명령의 선택적 `date`는 엄격한 `YYYY-MM-DD`입니다. 생략하면 오늘을 사용하고, 본문만 수정할 때 관리 날짜는 유지합니다. 과거/미래 항목은 해당 날짜를 명시해야 하며 자정 이후 오래된 기본 날짜의 후보를 실행하지 않습니다.

`ReminderInput`은 `clock`·`after`·`daily`·`weekly` 중 하나입니다. `clock`은 다음 `HH:mm`에 한 번, `after`는 지정 분 뒤에 한 번, `daily`는 매일, `weekly`는 지정 요일의 로컬 시각에 반복합니다. 요일은 일요일 0~토요일 6입니다. 메모 수정의 `reminder` 생략은 기존 예약 유지, `null`은 해제입니다. 구체적인 필드·범위는 `src/main/features/app-commands.ts`와 `src/main/ai/prompt.ts`가 기준입니다.

모델에 메모·근무 파일 전체나 내부 ID 목록을 직접 제공하지 않습니다. 모델은 사용자가 말한 검색어를 제안하며, 이전에 사용자가 요청해서 답변 이력에 남은 조회 결과는 후속 질문에도 전달됩니다. main이 실제 항목을 조회하며 수정·완료 대상이 여럿이면 후보 번호를 묻습니다. 같은 본문 항목도 임의로 선택하지 않습니다. 선택 전 변경된 후보에는 오래된 요청을 적용하지 않습니다. 날짜를 생략한 근무 부분 수정은 기존 출근일을 유지하며 “오늘” 같은 명시적인 날짜 요청은 로컬 날짜 기준으로 계획합니다.

잘못된 JSON·미지원 명령·허용하지 않은 명령 필드·범위 오류는 실행하지 않습니다. 자유 형식 답변을 코드나 셸로 실행하지 않습니다. 실제 저장 결과를 main이 확인한 뒤 성공 문장을 만들며 저장 실패를 완료로 표시하지 않습니다. 삭제는 관리 패널의 확인 절차로 수행합니다.

## 대화 이력과 전달되는 정보

질문·답변은 새 대화 또는 앱 종료까지 메모리에 보관하며 사용자가 이력 전체를 볼 수 있습니다. 취소·실패한 질문은 상태와 함께 남습니다. 창·말풍선을 닫아도 이력·초안·진행 요청을 유지합니다. **새 대화**는 진행 요청과 모호한 대상 선택을 취소하고 이력을 비웁니다. 대화를 파일로 장기 보관하지 않습니다.

메모·근무시간 파일 전체를 일반 대화에 자동 제공하지 않습니다. 다만 **사용자가 요청한 조회·요약·실행 결과는 사용자에게 보이는 답변으로 이력에 남고 다음 질문에도 전달**됩니다. 이를 지우려면 새 대화를 시작합니다. 명령 계획에는 현재 로컬 날짜·시각·요일을 별도 `app_context`로 전달합니다. 이 메타데이터나 개발 지침·인증·개인 설정을 이전 사용자 발화로 취급하지 않습니다.

현재 질문은 1~4,000자, 답변은 최대 16,000자입니다. 질문·이력·답변 여유분을 포함한 요청 제한은 200,000자이며 이력을 몰래 잘라내지 않습니다. 제한에서는 새 대화를 안내합니다.

## Codex 준비와 제한된 실행

- Codex CLI `0.154.0` 이상을 설치하고 터미널에서 `codex login`으로 로그인합니다. [설치 안내](https://developers.openai.com/codex/cli)와 [비대화형 실행 안내](https://developers.openai.com/codex/noninteractive)를 참고하세요.
- 캐릭터 좌클릭·AI 말풍선·우클릭 메뉴·`⌘⇧Enter`·메뉴 막대로 대화 창을 엽니다. 첫 진입과 **다시 확인**은 버전·필수 옵션·로그인 상태를 검사하며 모델 요청은 하지 않습니다.
- 실행 파일은 PATH, Homebrew, `~/.local/bin`, nvm에서 찾습니다. 필요하면 앱 실행 환경의 `DESKMATE_CODEX_PATH`로 지정합니다. 개인 절대경로·설정은 공유 소스에 넣지 않습니다.
- CLI의 기존 인증을 재사용하며 앱이 인증 파일·API 키를 읽어 복사하거나 별도로 저장하지 않습니다. 원문 진단·인증 상태 출력은 고정 안내로 바꾸어 UI에 전달합니다.
- 질문마다 빈 임시 폴더에서 실행합니다. 질문·이력·현재 시각은 stdin의 JSON으로 전달하고 실행 파일·인자를 분리하며 `shell: false`를 사용합니다.
- `--json`, `--ephemeral`, `--ignore-user-config`, `--sandbox read-only`와 승인 요청 금지 옵션을 유지합니다. 셸·브라우저·연결 앱·플러그인·훅·기억 등의 도구를 비활성화합니다.
- 앱 전용 지침 파일을 임시 폴더에 권한 `0600`으로 만들고 `model_instructions_file`로 기본 코딩 역할을 대체합니다. `project_doc_max_bytes=0`·스킬 안내 차단으로 개발 지침 혼입을 막으며 개인 전역 파일은 수정하지 않습니다. 종료 후 임시 폴더를 정리합니다.
- 모델 이름은 고정하지 않고 CLI 기본값을 사용합니다. 개인 CLI 설정을 불러오지 않으므로 그 파일의 모델·도구 설정도 적용하지 않습니다.
- 앱 명령 추가가 CLI의 파일·도구 권한을 넓히지 않습니다. AI는 JSON 제안만 반환하고 메모·근무 파일은 앱 서비스만 수정합니다. 실시간 검색과 임의 로컬 파일 작업은 지원하지 않습니다.

읽기 전용은 CLI 실행 정책이며 별도 운영체제 가상 환경을 만들지 않습니다. CLI의 인증 캐시·자체 운영 기록은 CLI 관리 범위이고 `--ephemeral`은 세션 파일 저장을 생략합니다.

## 요청 수명과 표시

연결 검사나 질문은 한 번에 하나입니다. 연결 검사 명령당 5초, 질문 명령은 120초로 제한하며 질문 실행 전에 버전·옵션·인증을 다시 확인합니다. 표준 출력·오류가 제한을 넘으면 종료합니다.

JSONL의 완료된 Agent 메시지와 정상 종료·`turn.completed`가 모두 있어야 Provider 성공입니다. 빈 답변·길이 초과·파싱 실패·비정상 종료는 오류입니다. 취소는 요청 ID를 검사해 프로세스 그룹을 종료하며 취소·종료·새 대화 이후 늦은 응답은 앱 명령을 실행하거나 이력을 바꾸지 못합니다.

대화 창과 말풍선에 **응답 생성 중…**을 표시합니다. 접기는 표시만 숨기고 **취소**는 요청을 종료합니다. 생성 중에는 알림 점프를 하지 않습니다. 실제 메모 알림이 AI 말풍선보다 우선하며 드래그·놓기·우클릭 메뉴 조작 동안 새 표시는 미룹니다.

사용자에게 보이는 답변은 일반 텍스트이며 HTML로 실행하지 않습니다. 긴 답변은 창·말풍선 안에서 스크롤하고 텍스트를 선택할 수 있습니다. Enter 전송·Shift+Enter 줄바꿈을 지원하며 한국어 조합 중 Enter는 보내지 않습니다. 대화 단축키는 기본 `⌘⇧Enter`를 사용하며 변경 UI는 제공하지 않습니다.

## 개인 Agent에 연결 교체 요청하기

프로젝트 폴더에서 사용하는 개인 Agent에 다음과 같이 요청할 수 있습니다.

> `docs/agent-provider-guide.md`와 `src/main/ai/provider.ts`를 읽고 내가 사용하는 AI 연결로 어댑터를 교체해줘. 연결 도구·로그인 방식·응답 형식은 먼저 확인해줘. 공통 질문·이력·취소·appCommands 계약과 JSON reply/command envelope를 유지하고, 앱 명령은 기존 AppCommandService만 실행하게 해줘. 개인 설정·인증 파일을 소스에 넣지 말고 메모·근무·반복 알림·날짜별 메모·캐릭터 코드는 유지해줘. 가짜 Provider 테스트부터 확인하고 실제 연결 점검과 빌드 결과를 구분해서 알려줘.

연결 교체 시 필요한 점검은 다음과 같습니다.

1. 연결 도구 미설치·미인증·오류가 원문 진단 대신 공통 상태로 표시되는지
2. 일반 답변·조회·변경의 envelope, 잘못된 JSON·미지원 명령 거부가 유지되는지
3. 후속 대화·모호한 메모의 번호 선택·변경된 후보 거부가 유지되는지
4. 저장 실패·취소·시간 초과·새 대화 뒤 늦은 결과가 데이터를 바꾸지 않는지
5. 생성 중 말풍선·알림 우선순위·위젯과 패널 IPC 권한이 유지되는지
6. 개인 설정·실경로·인증·업무 데이터가 공유 소스나 로그에 포함되지 않는지

새 어댑터의 단위 점검, 실제 모델 연결, 빌드·패키징, 설치 앱의 수동 조작은 서로 다른 검증 단계입니다. 수행하지 않은 단계를 완료로 기록하지 않습니다.
