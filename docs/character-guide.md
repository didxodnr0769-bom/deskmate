# AI Agent로 캐릭터 바꾸기

Agent 설치·로그인이나 clone한 폴더를 여는 과정부터 시작하려면 [커스터마이징 시작 안내](customization.md)를 먼저 확인하세요.

이 프로젝트 폴더에서 Codex나 Claude Code를 실행하고 원하는 외형을 요청하면, Agent가 캐릭터 소스와 그 외형에 어울리는 동작을 함께 수정하는 방식입니다. 기본 제공 캐릭터는 코드로 그린 돌멩이·검은 고양이·크림 토끼와 로컬 스프라이트로 재생하는 첼시·츄츄이며, 처음에는 돌멩이를 사용합니다. 관리 패널의 **캐릭터** 탭에서 선택할 수 있습니다.

## 요청 예시

> 기본 돌멩이를 통통한 검은 고양이로 바꿔줘. `docs/character-guide.md`와 `docs/architecture.md`를 먼저 읽고, 외형뿐 아니라 대기·걷기·잡힘·놓기·알림을 고양이에 어울리게 함께 바꿔줘. 클릭 영역을 새 윤곽에 맞추고, 캐릭터 위 HP 게이지와 기존 드래그·패널·모니터 이동은 유지해줘. 변경 후 빌드하고 화면 점검 결과를 알려줘.

사용자는 이미지 파일 규격을 직접 맞추거나 앱 안에서 생성 서비스를 설정할 필요가 없습니다. Agent는 기본적으로 프로젝트의 그리기 코드를 수정할 수 있습니다. 별도 이미지나 스프라이트를 쓰려면 해당 자산을 프로젝트 안에 포함하고 로컬 로딩·크기·라이선스를 함께 확인하세요.

## 수정 위치

| 파일 | 역할 |
| --- | --- |
| `src/renderer/characters/rock.ts`, `cat.ts`, `rabbit.ts`, `chelsea.ts`, `chuchu.ts` | 각 외형, 동작별 포즈, 클릭 윤곽과 알림 점프 |
| `src/renderer/characters/index.ts` | 선택 ID와 캐릭터 정의의 연결 |
| `src/renderer/character-runtime.ts` | `CharacterDefinition` 계약과 Canvas 장면 렌더링, 공통 HP 표현 |
| `src/renderer/main.tsx` | 선택한 캐릭터 렌더러 연결, 패널·말풍선 UI |
| `src/shared/appearance.ts` | 선택 가능한 ID·이름, 크기 선택·창 배치와 실제 장면 배율 |
| `src/renderer/CharacterSettings.tsx` | 캐릭터 종류·크기 설정 UI와 프리뷰 |
| `src/shared/contracts.ts` | 앱 전체가 사용하는 상태·명령 계약 |

기본 캐릭터를 수정하거나 `src/renderer/characters/fox.ts`처럼 새 정의를 만들 수 있습니다. 새 정의는 `characters/index.ts`의 registry와 `src/shared/appearance.ts`의 `CHARACTER_OPTIONS`에 같은 ID로 등록하세요. 공유 ID 검증과 선택 UI는 이 목록을 사용합니다. 프리뷰와 실제 캐릭터가 같은 정의를 사용하며 파일 추가만으로 자동 선택되지는 않습니다.

외형 수정은 캐릭터 정의 파일을 중심으로 진행합니다. 공통 HP·패널 배치나 크기까지 바꾸는 경우에만 runtime·UI를 함께 조정합니다. 근무시간·메모·알림 스케줄·AI 연결은 캐릭터 제작 책임에 넣지 않습니다.

## 캐릭터 계약

`CharacterDefinition`의 정확한 타입은 `src/renderer/character-runtime.ts`가 기준입니다.

| 항목 | 작성할 내용 |
| --- | --- |
| `id`, `label` | 캐릭터 식별자와 사용자에게 보이는 이름 |
| `hitPolygon` | 기본 클릭 윤곽. 고정 외형과 스프라이트 로드 실패 시 사용 |
| `prepare()` (선택) | 로컬 자산 준비. 프리뷰는 완료 후 다시 그리기 |
| `getGeometry(state, epochNow)` (선택) | 현재 프레임의 여러 클릭 윤곽과 HP의 로컬 Y 기준점 |
| `notification` | 알림 점프 횟수·한 번의 시간(ms)·높이 |
| `getPose(state, epochNow)` | 현재 상태의 위치·회전·가로세로 배율 |
| `draw(context, state, epochNow)` | 로컬 원점을 기준으로 캐릭터 그리기 |

로컬 원점 `(0, 0)`은 캐릭터 발밑입니다. 논리 장면은 `280 × 300`이고 발밑은 장면 좌표 `(140, 266)`에 놓입니다. 캐릭터 위쪽은 음수 Y 좌표로 그립니다. HP는 runtime이 그리며 `getPose`의 X·Y 이동을 따라갑니다. 선택적인 `getGeometry`의 `hpY`는 발밑에 상대적인 HP 상단 위치이며, 없으면 기존 -95를 사용합니다. 사용자가 선택한 크기는 장면·클릭 윤곽에 공통으로 적용되므로 캐릭터 정의에서 별도 배율을 곱하지 않습니다. 말풍선은 HP 위치를 따라가되 글자 크기는 유지합니다.

`getPose`가 반환하는 `rotation`은 라디안, `x`·`y`는 장면 좌표 이동량, `scaleX`·`scaleY`는 배율입니다. runtime이 그리기와 클릭 윤곽에 같은 변환을 적용합니다. `draw` 안에서만 팔다리를 크게 움직이면 고정된 `hitPolygon`과 어긋날 수 있으므로 실제 클릭도 확인하세요.

`epochNow`와 `state.motionStartedAt`은 모두 `Date.now()` 기준의 밀리초입니다. 애니메이션 경과 시간은 두 값을 빼서 계산하세요. `requestAnimationFrame`의 `performance` 타임스탬프를 직접 빼면 시간 기준이 달라집니다.

## 외형과 함께 바꿀 동작

| 상태 | 의미 | 돌멩이 예시 | 고양이 예시 |
| --- | --- | --- | --- |
| `idle` | 잠시 대기 | 미세하게 기울거나 숨 쉬듯 변형 | 앉아서 꼬리 움직이기·눈 깜빡이기 |
| `walking` | 작업 영역 안에서 X·Y 이동 | 짧게 통통 튀거나 굴러가기 | 이동 방향에 맞춰 발 움직이기 |
| `dragged` | 커서에 잡혀 이동 | 살짝 흔들리기 | 몸을 늘어뜨리거나 발 움직이기 |
| `dropping` | 놓은 위치에서 짧게 반응 | 제자리에서 작게 튀기 | 몸을 낮췄다 펴기 |
| `notify` | 무음 알림 | 몇 번 점프한 뒤 정지 | 귀와 몸을 반응시키며 점프 |

모든 상태를 처리하고 `state.direction`의 `1`·`-1`에 맞춰 좌우 표현을 조정하세요. 실제 좌우 그림이 따로 있는 스프라이트는 `scaleX: 1`로 그리고 올바른 방향 프레임을 선택합니다. 알림 점프가 끝나도 예약 알림 말풍선은 사용자가 닫을 때까지 유지해야 합니다. 가벼운 자발 대화의 빈도·야간 억제·자동 닫기는 main의 `CasualConversation`이 담당하며 캐릭터 그리기에서 별도 말풍선이나 소리를 만들지 않습니다.

창의 실제 X·Y 이동·드래그·경계 반사와 상태 전환은 main 프로세스가 담당합니다. 드래그를 놓으면 창이 작업 영역 안의 해당 위치를 유지합니다. `dropping`은 이 자리에서 280ms 동안 보여주는 포즈이며, 캐릭터 정의는 이 구간의 시각 반응을 작성합니다.

HP는 저장한 근무시간을 기준으로 main이 계산합니다. 외형을 바꿀 때는 전달받은 `state.hp`를 표시하고, 캐릭터 파일에 별도의 근무시간 계산·저장을 넣지 마세요.

말풍선이 있는 동안 평상시에는 `notify` 상태를 유지합니다. 드래그·놓기 동작은 잠시 우선하며 조작이 끝나면 `notify`로 돌아옵니다. 코드로 그리는 캐릭터는 `notification` 설정에 맞춰 점프를 끝내고, 이후에는 그 자리에서 기다리도록 `getPose`를 작성하세요. 첼시·츄츄는 점프 대신 고개·귀 반응 프레임을 보여준 뒤 기다립니다. 앱의 상태 이름과 IPC를 캐릭터마다 새로 만들지 않습니다.

## 첼시·츄츄 방향별 동작

`src/renderer/assets/chelsea-pet.png`와 `chuchu-pet.png`의 8×8 프레임은 각 캐릭터의 `*-animation.ts` 선택 규칙과 한 세트입니다. 재생에는 네트워크·이미지 생성 서비스·AI API 키가 필요하지 않습니다. 제작 프롬프트는 같은 폴더의 `chelsea-pet.prompts.txt`·`chuchu-pet.prompts.txt`에 있으며 원본 참고 사진은 배포하지 않습니다.

| 행 (0부터) | 내용 |
| --- | --- |
| 0 | 정면 대기·눈 깜빡임·둘러보기 |
| 1, 2 | 왼쪽·오른쪽 측면의 네 발 보행 |
| 3 | 정면에서 좌우 방향으로 돌리는 자세 |
| 4 | 첼시: 앞발 핥기·세수 / 츄츄: 발 핥기·귀 긁기 |
| 5 | 기지개·앉기 |
| 6 | 웅크려 눕기·졸기, 기상 시 역재생 |
| 7 | 알림·생각·잡힘·착지 반응 |

main의 `PetBehavior`가 목적지와 행동을 정합니다. 보행은 전달된 논리 이동 거리로 프레임을 선택하고, 휴식·전환은 epoch 시각으로 재생합니다. 기존 `Motion`은 조작과 알림의 우선순위를 유지하며, 별도의 선택적 `state.pet`가 자율 행동을 표현합니다. 다른 캐릭터에 이를 적용하려면 방향별 자산·fallback·개별 프레임 선택기를 추가하고 `appearance.ts`의 `usesPetBehavior`에 해당 ID를 연결하세요. `createPetSpriteLoader`가 자산별 캐시를 만들고 `createSpritePetCharacter`가 공통 그리기·포즈·클릭 윤곽을 연결합니다. `pet-animation.ts`는 공통 타이밍을 제공하며 방향 전환의 셀 배치는 각 선택기에 둡니다.

첼시 보행은 `chelsea-walk-rig.png`의 2열×4행 재료(오른쪽/왼쪽 몸통, 앞다리 위/아래, 뒷다리 위/아래, 앞발/뒷발)와 `chelsea-gait.ts`·`chelsea-walk-rig.ts`를 함께 수정합니다. 공통 몸통 크기·기준점·지면선과 발끝 경로를 유지하세요. 현재 다리 외피는 위쪽 재료의 회색 털 영역을 곡선으로 연결하며 개별 아래쪽·발목 조각의 끝은 사용하지 않습니다. 발의 회색 윗부분과 외피가 이어져야 합니다. 56px 보폭의 실제 수평 이동량으로 연속 자세를 그리며, 기본 시트는 나머지 자세와 재료 로딩 실패 시 대체 보행에 사용합니다. 시작·정지는 `chelsea-turn.png`의 4열×2행 단일 몸통 자세로 연결합니다. 재료의 비율·털 연결과 전환을 실제 크기로 보고, 전체 몸통 디졸브와 거절된 16장 시트를 다시 연결하지 마세요. [보행 재검토](chelsea-gait.md)에 실패 원인과 기준을 기록했습니다.

생성 시트의 간격이 균일하지 않을 수 있어 `sprite-components.ts`가 시트별 행·열 수에 맞는 alpha 연결 성분(기본 시트 64개, 첼시 관절 재료 8개)을 분리하고, 실제 발밑 순서로 8개씩 묶어 각 행의 가로 순서를 정합니다. 각 캐릭터는 하나의 연결된 본체여야 하며 큰 연결 성분 수가 다르면 해당 시트를 사용하지 않습니다. 이웃 캐릭터와 겹친 경계 상자의 픽셀은 제외하고 본체와 인접한 반투명 가장자리만 보존합니다. 각 프레임의 실제 alpha 윤곽을 로딩할 때 계산하고 모든 프레임에 공통 배율을 사용합니다. 발밑을 정렬하며 현재 자세의 여러 polygon을 클릭 영역으로 전달합니다. 크기를 바꿔도 같은 도형과 배율을 사용해야 합니다. 스프라이트 로드 실패 시 `chelsea-fallback.ts`·`chuchu-fallback.ts`가 해당 캐릭터의 외형을 유지합니다. 운영체제의 동작 줄이기 설정에서는 대표 정지 프레임을 사용합니다.

## 검증

```sh
npm run build
npm test
npm start
```

빌드는 타입 검사도 포함합니다. 앱에서 다음을 직접 확인하세요.

- 대기·걷기·잡기·놓기·알림이 새 외형에 어울리는지
- 그림과 클릭 윤곽이 일치하고 빈 영역은 뒤쪽 앱을 클릭할 수 있는지
- HP 게이지, 알림 말풍선, 캐릭터가 서로 가리지 않는지
- X·Y 이동·경계 반사와 모니터 사이 드래그가 유지되는지
- 드래그를 놓은 위치에서 짧게 반응한 뒤 이동을 이어가는지
- 크기가 다른 화면과 배율에서도 그림이 잘리거나 흐려지지 않는지

공통 동작 점검은 [검증 안내](verification.md)를 따릅니다. 화면 확인 없이 외형과 동작이 모두 검증됐다고 기록하지 마세요.
