# AI Agent로 캐릭터 바꾸기

이 프로젝트 폴더에서 Codex나 Claude Code를 실행하고 원하는 외형을 요청하면, Agent가 캐릭터 소스와 그 외형에 어울리는 동작을 함께 수정하는 방식입니다. 초기 캐릭터는 Canvas 2D로 그린 돌멩이입니다.

## 요청 예시

> 기본 돌멩이를 통통한 검은 고양이로 바꿔줘. `docs/character-guide.md`와 `docs/architecture.md`를 먼저 읽고, 외형뿐 아니라 대기·걷기·잡힘·놓기·알림을 고양이에 어울리게 함께 바꿔줘. 클릭 영역을 새 윤곽에 맞추고, 캐릭터 위 HP 게이지와 기존 드래그·패널·모니터 이동은 유지해줘. 변경 후 빌드하고 화면 점검 결과를 알려줘.

사용자는 이미지 파일 규격을 직접 맞추거나 앱 안에서 생성 서비스를 설정할 필요가 없습니다. Agent는 기본적으로 프로젝트의 그리기 코드를 수정할 수 있습니다. 별도 이미지나 스프라이트를 쓰려면 해당 자산을 프로젝트 안에 포함하고 로컬 로딩·크기·라이선스를 함께 확인하세요.

## 수정 위치

| 파일 | 역할 |
| --- | --- |
| `src/renderer/characters/rock.ts` | 기본 외형, 동작별 포즈, 캐릭터 윤곽, 알림 점프 설정 |
| `src/renderer/character-runtime.ts` | `CharacterDefinition` 계약과 Canvas 장면 렌더링, 공통 HP 표현 |
| `src/renderer/main.tsx` | 사용할 캐릭터 import와 렌더러 연결, 패널·말풍선 UI |
| `src/shared/appearance.ts` | 크기 선택·창 배치와 실제 장면 배율 |
| `src/renderer/CharacterSettings.tsx` | 캐릭터 크기 설정 UI |
| `src/shared/contracts.ts` | 앱 전체가 사용하는 상태·명령 계약 |

기본 캐릭터를 바로 수정하거나 `src/renderer/characters/cat.ts`처럼 새 파일을 만들 수 있습니다. 새 파일을 만들었다면 `main.tsx`가 가져오는 캐릭터와 렌더링 호출을 새 정의로 연결하세요. 파일을 추가하는 것만으로 자동 선택되지는 않습니다.

외형 수정은 캐릭터 정의 파일을 중심으로 진행합니다. 공통 HP·패널 배치나 크기까지 바꾸는 경우에만 runtime·UI를 함께 조정합니다. 근무시간·메모·알림 스케줄·AI 연결은 캐릭터 제작 책임에 넣지 않습니다.

## 캐릭터 계약

`CharacterDefinition`의 정확한 타입은 `src/renderer/character-runtime.ts`가 기준입니다.

| 항목 | 작성할 내용 |
| --- | --- |
| `id`, `label` | 캐릭터 식별자와 사용자에게 보이는 이름 |
| `hitPolygon` | 그림의 윤곽을 따라 클릭할 수 있는 로컬 좌표 점 목록 |
| `notification` | 알림 점프 횟수·한 번의 시간(ms)·높이 |
| `getPose(state, epochNow)` | 현재 상태의 위치·회전·가로세로 배율 |
| `draw(context, state, epochNow)` | 로컬 원점을 기준으로 캐릭터 그리기 |

로컬 원점 `(0, 0)`은 캐릭터 발밑입니다. 논리 장면은 `280 × 300`이고 발밑은 장면 좌표 `(140, 266)`에 놓입니다. 캐릭터 위쪽은 음수 Y 좌표로 그립니다. HP는 runtime이 그리며 `getPose`의 X·Y 이동을 따라갑니다. 사용자가 선택한 크기는 장면·클릭 윤곽에 공통으로 적용되므로 캐릭터 정의에서 별도 배율을 곱하지 않습니다. 말풍선은 HP 위치를 따라가되 글자 크기는 유지합니다.

`getPose`가 반환하는 `rotation`은 라디안, `x`·`y`는 장면 좌표 이동량, `scaleX`·`scaleY`는 배율입니다. runtime이 그리기와 클릭 윤곽에 같은 변환을 적용합니다. `draw` 안에서만 팔다리를 크게 움직이면 고정된 `hitPolygon`과 어긋날 수 있으므로 실제 클릭도 확인하세요.

`epochNow`와 `state.motionStartedAt`은 모두 `Date.now()` 기준의 밀리초입니다. 애니메이션 경과 시간은 두 값을 빼서 계산하세요. `requestAnimationFrame`의 `performance` 타임스탬프를 직접 빼면 시간 기준이 달라집니다.

## 외형과 함께 바꿀 동작

| 상태 | 의미 | 돌멩이 예시 | 고양이 예시 |
| --- | --- | --- | --- |
| `idle` | 잠시 대기 | 미세하게 기울거나 숨 쉬듯 변형 | 앉아서 꼬리 움직이기·눈 깜빡이기 |
| `walking` | 작업 영역 안에서 X·Y 이동 | 짧게 통통 튀거나 굴러가기 | 이동 방향에 맞춰 발 움직이기 |
| `dragged` | 커서에 잡혀 이동 | 살짝 흔들리기 | 몸을 늘어뜨리거나 발 움직이기 |
| `dropping` | 놓은 위치에서 짧게 반응 | 제자리에서 작게 튀기 | 몸을 낮췄다 펴기 |
| `notify` | 무음 알림 | 몇 번 점프한 뒤 정지 | 귀와 몸을 반응시키며 점프 |

모든 상태를 처리하고 `state.direction`의 `1`·`-1`에 맞춰 좌우 표현을 조정하세요. 알림 점프가 끝나도 말풍선은 사용자가 닫을 때까지 유지해야 합니다. 평상시에 임의의 말풍선이나 소리를 추가하지 않습니다.

창의 실제 X·Y 이동·드래그·경계 반사와 상태 전환은 main 프로세스가 담당합니다. 드래그를 놓으면 창이 작업 영역 안의 해당 위치를 유지합니다. `dropping`은 이 자리에서 280ms 동안 보여주는 포즈이며, 캐릭터 정의는 이 구간의 시각 반응을 작성합니다.

HP는 저장한 근무시간을 기준으로 main이 계산합니다. 외형을 바꿀 때는 전달받은 `state.hp`를 표시하고, 캐릭터 파일에 별도의 근무시간 계산·저장을 넣지 마세요.

말풍선이 있는 동안 평상시에는 `notify` 상태를 유지합니다. 드래그·놓기 동작은 잠시 우선하며 조작이 끝나면 `notify`로 돌아옵니다. 캐릭터의 `notification` 설정에 맞춰 점프를 끝내고, 이후에는 그 자리에서 기다리도록 `getPose`를 작성하세요. 앱의 상태 이름과 IPC를 캐릭터마다 새로 만들지 않습니다.

## 검증

```sh
npm run build
npm test
npm start
```

빌드는 타입 검사도 포함합니다. 앱에서 다음을 직접 확인하세요.

- 대기·걷기·잡기·놓기·알림이 새 외형에 어울리는지
- 그림과 클릭 윤곽이 일치하고 빈 영역은 뒤쪽 앱을 클릭할 수 있는지
- HP 게이지, 알림 말풍선, 캐릭터가 서로 가리지 않는지
- X·Y 이동·경계 반사와 모니터 사이 드래그가 유지되는지
- 드래그를 놓은 위치에서 짧게 반응한 뒤 이동을 이어가는지
- 크기가 다른 화면과 배율에서도 그림이 잘리거나 흐려지지 않는지

공통 동작 점검은 [검증 안내](verification.md)를 따릅니다. 화면 확인 없이 외형과 동작이 모두 검증됐다고 기록하지 마세요.
