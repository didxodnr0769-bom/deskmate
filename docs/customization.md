# 내 Agent로 DeskMate 커스터마이징하기

DeskMate의 중심은 **저장소를 내려받고, 자신의 코딩 Agent와 기능·캐릭터를 추가해 사용하는 것**입니다.
기본 기능을 실행해 보고, 원하는 점을 한 가지씩 바꾸고, 다시 실행하며 나만의 동료를 만들어 보세요.

이 안내는 clone → Agent에서 프로젝트 열기 → 변경 요청 → 검증·실행 → 내 앱 만들기 순서입니다.

## 1. 준비하기

- macOS, Git, Node.js 24를 준비합니다. 프로젝트의 `.nvmrc`도 Node.js 24를 지정합니다.
- 파일 읽기·수정과 터미널 실행이 가능한 코딩 Agent를 준비하고, 해당 도구에서 설치·로그인을 마칩니다.
- Codex·Claude Code·IDE의 Agent 모드 등을 사용할 수 있습니다. 이미지 생성 도구의 지원 여부는 각 Agent 환경에 따릅니다.

Agent의 인증과 권한은 그 도구에서 관리합니다. DeskMate 설정 화면에 Agent 계정이나 API 키를 등록하는 절차는 없습니다.

| 하려는 일 | 어디에서 하나요? |
| --- | --- |
| 기능·캐릭터·소스를 바꾸기 | 코딩 Agent에서 clone한 `deskmate` 폴더를 열고 요청 |
| 만들어진 앱의 메모·근무 조회와 변경, 대화 | 실행한 DeskMate의 선택적인 대화 창 |

프로젝트 수정에는 앱 내 대화 연결이 필요하지 않습니다. 앱 내 대화의 연결 방식을 바꾸고 싶다면 [Provider 교체 안내](agent-provider-guide.md)를 이어서 참고하세요.

## 2. 프로젝트 내려받고 기본 앱 실행하기

터미널에서 원하는 작업 위치로 이동한 뒤 실행합니다.

```sh
git clone https://github.com/didxodnr0769-bom/deskmate.git
cd deskmate
git switch -c my-companion
npm ci
npm run dev
```

`my-companion`은 개인 수정용 브랜치의 예시 이름입니다. 기본 앱을 한 번 실행해 변경 전 모습을 확인하세요.
본인 GitHub에도 수정본을 보관하고 싶다면 먼저 저장소를 Fork하고 **자신의 Fork 주소**로 clone할 수 있습니다. 로컬에서만 고쳐 쓸 때는 위 명령으로 충분합니다.

`npm ci`는 Electron 실행 파일도 내려받습니다. 다운로드가 중단되면 [설치 문제 안내](usage.md#실행과-기본-조작)를 확인하세요.
앱의 메뉴 막대에서 **종료**하거나 관리 패널의 **앱 종료**를 눌러 다음 수정 작업을 준비합니다. 창 닫기나 숨기기는 앱 종료와 다릅니다.

## 3. 내 Agent에서 프로젝트 열기

작업 폴더는 `package.json`, `AGENTS.md`, `src/`가 들어 있는 **clone한 저장소 루트**로 지정합니다.
Agent가 이 폴더를 읽고 수정하며 빌드 명령을 실행할 수 있는지 확인하세요.

### Codex 앱 또는 IDE에서

Codex에서 로컬 프로젝트·폴더를 열고 `deskmate`를 선택한 뒤 코딩 작업 대화를 시작합니다.
IDE 확장을 사용한다면 편집기에서 같은 폴더를 열고 Agent가 파일을 수정할 수 있는 모드로 시작하세요.
화면별 설치·로그인 방법은 [공식 Codex 시작 안내](https://developers.openai.com/codex/quickstart)를 참고하세요.

### Codex CLI에서

[공식 CLI 안내](https://developers.openai.com/codex/cli)에 따라 설치한 다음, clone한 폴더에서 실행합니다.

```sh
cd deskmate
codex
```

이미 `deskmate` 안에 있다면 `cd` 없이 `codex`만 실행합니다. 처음 실행할 때 안내되는 로그인 절차를 완료하세요.

### Claude Code에서

[공식 빠른 시작](https://code.claude.com/docs/en/quickstart)에 따라 설치한 다음, clone한 폴더에서 실행합니다.

```sh
cd deskmate
claude
```

이미 폴더 안이라면 `claude`만 실행하고 첫 실행의 로그인 안내를 따릅니다.
이 저장소의 `CLAUDE.md`는 `@AGENTS.md`로 공통 지침을 가져옵니다. 가져오기 방식은 [공식 지침 안내](https://code.claude.com/docs/en/memory#share-one-file-with-other-coding-tools)를 참고하세요.

다른 Agent에서도 이 폴더를 작업 대상으로 열고 아래 첫 요청을 보내면 됩니다. 실제 파일 수정 권한과 명령 실행 범위는 사용 중인 도구에서 확인하세요.

## 4. 첫 요청으로 프로젝트 맥락 전달하기

Agent 대화에 다음을 복사해 보내세요.

```text
이 프로젝트를 내 취향에 맞게 커스터마이징할 거야.
먼저 AGENTS.md, .agents/README.md, docs/customization.md,
docs/architecture.md를 읽고 현재 구조와 실행·검증 방법을 파악해줘.
내가 추가할 기능이나 캐릭터의 관련 소스 위치와 필요한 정보를 알려줘.
개인 설정·인증 정보와 원본 참고 사진은 공유 소스에 넣지 마.
```

Codex는 프로젝트의 `AGENTS.md`를 지침으로 사용하며, Claude Code는 `CLAUDE.md`에서 공통 지침을 가져옵니다.
자동 지침 탐색을 지원하지 않는 Agent도 위처럼 파일을 직접 읽도록 요청할 수 있습니다.
규칙 파일의 역할은 [Codex 공식 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)와 [Claude Code 공식 안내](https://code.claude.com/docs/en/memory)를 참고하세요.

이후에는 원하는 변경을 한 가지씩 요청합니다. Agent가 구현하고 빌드할 수 있도록 대상 파일·명령과 변경 내용을 확인하세요.

## 5. 원하는 변경 요청하기

### 설명으로 새 캐릭터 추가

```text
docs/character-guide.md를 읽고 통통한 다람쥐 캐릭터를 추가해줘.
기존 캐릭터는 유지하고 캐릭터 설정에서 새로 선택할 수 있게 해줘.
대기·좌우 걷기·잡기·놓기·알림 동작을 다람쥐에 맞추고,
그림과 클릭 윤곽, HP와 말풍선 위치도 함께 확인해줘.
관련 테스트와 빌드를 실행하고 실제 화면에서 확인한 범위를 알려줘.
```

### 내 사진으로 캐릭터 추가

사용 권리가 있는 사진을 Agent 대화에 첨부하고 이름·스타일·원하는 동작을 함께 알려 주세요.

```text
첨부한 반려동물 사진을 참고해서 '모모' 캐릭터를 추가해줘.
둥근 얼굴과 귀 모양을 살리고, 기존 캐릭터를 지우지 말아줘.
정면 대기, 좌우 이동, 쉬기·기지개·알림 반응을 자연스럽게 만들어줘.
사용 가능한 이미지 생성 도구가 있는지 먼저 확인하고,
없다면 준비된 로컬 이미지나 Canvas 코드로 구현 가능한 방법을 알려줘.
원본 사진은 저장소에 추가하지 말고, 배포할 완성 자산만 프로젝트에 포함해줘.
docs/character-guide.md에 맞춰 크기·클릭 영역·로딩 실패도 검증해줘.
```

이미지 생성 기능은 Agent마다 다릅니다. 준비한 이미지나 스프라이트를 연결하거나, 그리기 코드로 캐릭터를 만드는 방법도 있습니다.
구현 계약은 [캐릭터 가이드](character-guide.md), 참고 이미지와 결과물의 권리 범위는 [이미지 안내](assets.md)를 확인하세요.

### 필요한 기능 추가

```text
앱에 25분 집중 타이머를 추가해줘.
설정 화면에서 시작·중지하고 남은 시간을 확인할 수 있게 해줘.
시간이 끝나면 캐릭터 말풍선으로 알려주고, 중지하거나 앱을 종료한 뒤
늦은 완료 알림이 뜨지 않게 해줘.
기존 메모·근무시간·캐릭터 설정과 알림 우선순위는 유지해줘.
관련 검증과 빌드를 실행하고, 확인한 동작과 남은 수동 점검을 정리해줘.
```

추가 요청에는 **원하는 화면·동작·저장 여부·유지할 기존 기능**을 적으면 도움이 됩니다.
저장 형식을 바꾸는 기능은 기존 데이터 보존과 이전 버전 백업도 함께 요청하세요.
앱 내 대화에서 새 기능도 조작하려면 [앱 명령 계약](agent-provider-guide.md#앱-명령-envelope와-허용-범위)까지 연결하도록 요청할 수 있습니다.

## 6. 변경한 앱 확인하기

Agent에게 변경한 파일과 검증 결과를 설명하도록 요청한 뒤, 터미널에서 필요한 점검을 실행하거나 Agent에 실행을 요청하세요.

```sh
npm run build
npm test
npm start
```

빌드는 TypeScript 검사도 포함합니다. `npm start`는 이미 생성된 빌드를 실행합니다.
수정 후 한 번에 빌드·실행하려면 `npm run dev`를 사용하세요.

이미 실행 중인 DeskMate는 **종료한 뒤** 다시 시작합니다. `npm run dev`는 파일 변경을 자동 반영하는 감시형 서버가 아닙니다.
예전에 설치한 앱이 떠 있으면 단일 인스턴스 처리로 기존 앱이 열릴 수 있으므로 그 앱도 종료하세요.

새 캐릭터를 선택해 걷기·드래그·알림과 크기를 확인하고, 추가한 기능의 저장·오류 처리도 직접 살펴보세요.
테스트·빌드 통과와 화면·실제 AI 연결 확인은 서로 다른 점검입니다. 수행한 범위는 [검증 안내](verification.md)에 기록합니다.

변경이 마음에 들면 `git diff`로 확인한 뒤 로컬 커밋으로 남길 수 있습니다.

## 7. 내 Mac에서 쓸 앱 만들기

```sh
npm run package:mac
```

생성된 앱은 `release/Desktop Companion-darwin-<아키텍처>/Desktop Companion.app`입니다.
Agent에게 이 산출물의 경로와 실행 방법을 알려 달라고 요청하거나 직접 실행하세요. 앱은 만드는 Mac의 CPU 아키텍처를 따릅니다.
앱 이름·번들 ID를 바꾸는 커스터마이징은 기존 로컬 데이터 위치에도 영향을 줄 수 있으므로 데이터 이전을 함께 확인하세요.

새 문서나 공개 예제 이미지를 소스 ZIP에 넣고 싶다면 `scripts/source-archive.mjs`의 명시적 허용 목록도 함께 갱신해야 합니다.
개인 메모·인증·Agent 설정·참고 사진 원본은 커밋과 소스 ZIP에서 제외하세요. 앱 만들기와 로컬 데이터 위치는 [사용 안내](usage.md)에 있습니다.

## 막혔을 때

| 상황 | 확인할 내용 |
| --- | --- |
| Agent가 설명만 하고 파일을 바꾸지 않음 | 프로젝트 폴더·코딩 모드·파일 수정 권한과 실제 변경 요청인지 확인 |
| `codex`·`claude`를 찾을 수 없음 | 해당 도구의 공식 설치 안내를 따르고 새 터미널에서 다시 실행 |
| 이미지 생성 도구가 없음 | Canvas 코드로 그리기 또는 준비한 로컬 이미지 사용 |
| 바꾼 모습이 앱에 안 보임 | 기존 앱 종료 후 다시 빌드·실행했는지 확인 |
| 내 GitHub로 push할 수 없음 | 자신의 Fork나 저장소가 원격 대상으로 설정됐는지 확인 |

기본 기능의 버튼·메모·알림 조작은 [사용 안내](usage.md), 세부 구현은 [구조 안내](architecture.md)를 참고하세요.
