# 구조와 구현 범위

이 문서는 0.11.0 소스의 책임 분리와 데이터 계약을 설명합니다. 구현 여부와 실제 환경의 검증 완료 여부는 구분하며, 수행한 점검과 남은 수동 항목은 [검증 안내](verification.md)를 기준으로 확인합니다.

## 현재 프로세스 구조

~~~text
Electron main
  ├─ macOS 창·모니터·전역 단축키·캐릭터 이동
  ├─ 근무시간 계산·저장
  ├─ MemoService: 메모·일회성/반복 예약·확인·저장
  ├─ WorkBriefingService: 퇴근 전 할 일 요약·설정·확인
  ├─ ChatService: 대화 이력·새 대화·단일 요청·취소
  ├─ AgentProvider: 질문 → 답변 또는 앱 명령 JSON 제안
  ├─ AppCommandService: 허용 명령·대상·값 검증 → 앱 서비스 실행
  └─ 허용된 IPC 처리
       ↕
preload: window.companion
       ↕
renderer
  ├─ Canvas 2D 캐릭터·HP·말풍선
  ├─ React 근무·메모 관리 패널
  └─ 독립된 React 대화 창
~~~

`src/shared/contracts.ts`가 main과 renderer 사이의 상태·요청 형식을 정의합니다. preload는 앱에 필요한 기능만 노출하며 renderer에서 Node.js나 Electron API를 직접 호출하지 않습니다. AI가 제안한 명령도 main의 검증·도메인 서비스를 거칩니다.

## 캐릭터·창과 진입

캐릭터 상태는 `idle`, `walking`, `dragged`, `dropping`, `notify`입니다. 외형을 바꾸면 각 상태의 그림·움직임·클릭 윤곽도 함께 조정합니다. 업무 데이터와 예약 상태는 캐릭터 정의와 독립적입니다.

캐릭터는 작업 영역 안에서 X·Y 방향으로 이동합니다. 돌멩이·검은 고양이·크림 토끼는 두 축의 경계에서 반사됩니다. 첼시는 작업 영역 안의 짧은 목적지를 정하고 몸을 돌린 뒤 가속·감속하며 걷습니다. 다른 모니터로는 드래그해 이동합니다. 놓은 위치를 유지하며 영역을 벗어났을 때만 조정합니다. 280ms의 `dropping`은 포즈 표현이며 창을 바닥으로 옮기지 않습니다. `moveWidget`은 `nativePosition`으로 유한 좌표·반올림·int32 범위·음수 0을 검사합니다.

첼시의 선택적 `pet` 상태는 `idle/turn/walk/groom/stretch/sleep` 행동·방향·시작 시각·지속 시간·실제 이동 거리·속도를 전달합니다. `fromActivity`로 수면 후 기상을 표현합니다. main이 위치와 행동을 정하고 보행 중 상태는 최대 약 10Hz로 전송합니다. renderer는 전달된 거리와 최대 150ms의 속도 보간으로 발걸음을 재생합니다. 대화·관리 패널·메뉴·알림·숨김·드래그 중에는 이동 계획을 중단하고, 해제 후 현재 위치에서 다시 시작합니다. 이동을 꺼도 휴식 행동은 이어집니다. 이 상태는 저장하거나 AI에 요청하지 않습니다.

첼시의 `chelsea-pet.png`는 로컬 8×8 논리 배열의 투명 스프라이트입니다. 균일한 셀 간격을 가정하지 않고 alpha 연결 성분 64개를 실제 발밑·가로 순서로 분리해 이웃 자세의 픽셀을 제외합니다. 이미지 로드 때 프레임별 alpha 윤곽과 공통 배율을 계산하며, 그리기·클릭 영역·HP 높이는 같은 프레임 선택을 사용합니다. 읽지 못하면 기존 Canvas 외형을 사용합니다. 나머지 캐릭터는 고정 윤곽 계약을 유지합니다.

좌클릭은 대화 창을 열고 실제 드래그는 창을 열지 않습니다. 우클릭·Control+클릭은 네이티브 메뉴에서 대화하기·근무시간·메모로 진입합니다. 메뉴가 열린 동안 이동과 새 알림 표시를 미루며 닫거나 선택한 뒤 대기 항목을 처리합니다. 대상 관리 탭은 `panelNavigation`의 탭과 순번으로 전달해 같은 탭 재진입을 구분하고 입력 초안을 유지합니다.

AI 말풍선은 대화 창, 메모·퇴근 전 요약 말풍선은 메모 탭을 엽니다. 진입은 알림 확인·메모 완료를 수행하지 않습니다. 닫기·취소 버튼은 독립적으로 동작하며 텍스트 선택·스크롤·드래그는 화면 진입과 구분합니다. 말풍선 동작은 신뢰된 widget main frame과 현재 말풍선 ID를 검사합니다.

캐릭터 탭이나 우클릭의 **캐릭터 설정**에서 75·100·125·150% 크기를 선택합니다. 캐릭터와 HP는 같은 배율로 그리며 말풍선 글자 크기는 유지합니다. 창·클릭 윤곽·HP·말풍선을 함께 조정하고 화면 경계가 아니면 발밑의 위치를 유지합니다. 작은 화면에서는 실제 배율을 줄이고 말풍선 본문을 스크롤합니다.

`AppearanceService`는 `appearance.json`에 `{ version: 1, settings: { scale, characterId } }`를 권한 `0600`의 임시 파일·이름 변경으로 저장합니다. 기본 배율은 1, 종류는 `rock`입니다. `rock`·`cat`·`rabbit`·`chelsea`를 선택할 수 있고 종류와 크기를 재실행 후에도 유지합니다. 이전 크기 전용 설정은 원본을 바로 교체하지 않고 돌멩이로 읽습니다. 저장 실패는 설정·창을 바꾸지 않고 재시도를 허용합니다. 손상·미지원 파일은 덮어쓰지 않습니다. 설정 변경은 panel main frame만 요청합니다.

대화 창은 420×600이며 캐릭터를 따라 이동하지 않습니다. 기본 단축키는 `CommandOrControl+Shift+Return`이고 대화 창 설정에서 바꿉니다. 숨기기 단축키는 `CommandOrControl+Shift+Space`이며 근무 패널에서 바꿉니다. 충돌하면 기존 등록을 유지합니다. 위치·이동·단축키는 실행 중 상태입니다.

## 근무시간 계산과 저장

관리 패널의 초안과 적용된 근무시간을 구분합니다. 출근시간 변경은 퇴근시간을 기본 +9시간으로 채우며 이후 직접 고칠 수 있습니다. main이 날짜·시각을 다시 검증하고 저장 성공 후 상태를 갱신합니다. 대화 명령도 같은 저장 경로를 사용합니다.

- 날짜는 출근일의 로컬 날짜, 시각은 엄격한 `HH:mm`입니다.
- 퇴근시간이 출근시간보다 이르면 다음날 퇴근이며 같은 시각은 거절합니다.
- 출근 전 0%, 근무 중 내림한 0~99%, 퇴근 시각부터 100%입니다. 1초마다 갱신합니다.
- 캐릭터와 근무 패널의 HP는 표시한 정수 비율을 기준으로 0~20% 빨강, 21~40% 주황, 41~60% 노랑, 61~80% 기존 초록, 81~100% 진한 초록을 사용합니다.
- 남은 분은 올림하며 퇴근 이후 0분입니다.
- 저장한 출근일을 기준으로 계산하므로 자정·재실행이 새 근무일을 만들지 않습니다.
- 대화에서 날짜를 생략한 부분 수정은 기존 출근일을 유지합니다. 새 날짜를 지정하면 그 날짜에 필요한 근무 시각을 검증합니다.

`worktime.json`은 `{ version: 1, schedule: { date, startTime, endTime } }`입니다. 임시 파일을 쓴 뒤 이름을 바꾸어 교체하며 불러올 때 버전·날짜·시각을 검증합니다.

## 메모와 v4 저장

`MemoService`가 추가·수정·완료·완료 취소·삭제와 예약을 관리합니다. 본문은 앞뒤 공백을 제거한 1~1,000자이고 완료 항목을 포함해 최대 500개입니다. ID·생성 및 수정 시각은 main이 만듭니다. 삭제 전 확인은 관리 UI가 담당하며 대화 명령의 허용 목록에는 삭제가 없습니다.

예약 입력은 기존 `reminderTime: HH:mm | null`과 선택적인 `schedule`을 사용합니다.

| 표현 | 의미 |
| --- | --- |
| 알림 없음 | 예약하지 않음 |
| `reminderTime`만 지정 | 다음 해당 시각에 한 번 |
| `{ kind: 'once', dueAt }` | 저장된 순간에 한 번. 몇 분 뒤 요청은 이 형식으로 변환 |
| `{ kind: 'daily', time }` | 매일 로컬 시각 |
| `{ kind: 'weekly', time, weekdays }` | 선택한 요일의 로컬 시각. 일요일 0~토요일 6 |

사용자 입력에 연월일 필드를 추가하지 않습니다. 몇 분 뒤 예약은 생성 시 `dueAt`을 정하며 내용만 수정할 때 그 순간을 유지합니다. UI의 **다시 예약**은 저장 시점에 새 순간을 계산합니다.

`memos.json`의 현재 형식은 다음과 같습니다.

~~~text
{
  version: 4,
  memos: [{
    id, text, reminderTime, schedule?, completed, createdAt, updatedAt,
    reminder: null | { dueAt, acknowledged }
  }]
}
~~~

`createdAt`, `updatedAt`, `dueAt`은 밀리초 타임스탬프입니다. `schedule`은 공개 메모에 포함하지만 `reminder`는 main 내부 필드입니다. `MemoDraft.schedule: null`은 명시적인 알림 해제입니다. 본문만 수정할 때는 기존 예약 모드를 유지하고 명시적 시각 한 번 요청은 이전 반복 모드와 구분합니다.

파일 전체의 버전·항목·예약·개수·중복 ID를 검증합니다. 손상·미지원 버전이면 원본을 덮어쓰거나 일부 항목을 버리지 않고 메모 편집을 막습니다. 권한 `0600`·`wx`의 임시 파일을 쓴 뒤 이름을 바꾸며 저장 성공 후 메모리 상태를 갱신합니다.

v1/v2/v3를 읽을 수 있으며 읽기만으로 파일을 교체하지 않습니다. 첫 `getDueReminders` 또는 메모 변경에서 해당 버전 원본을 `memos.v1.backup.json`, `memos.v2.backup.json`, `memos.v3.backup.json`에 `wx`·`0600`으로 백업하고 v4를 저장합니다. 기존 일반 백업 파일은 보존합니다. 백업·저장 실패는 마이그레이션과 알림 전달을 보류하며 원본을 유지합니다.

v1의 ISO UTC `reminderAt`은 읽는 Mac의 로컬 `HH:mm`으로 바꿉니다. v1/v2의 미완료·시간 지정 항목은 업그레이드 시점에서 다음 로컬 시각에 한 번 예약합니다. v3의 저장된 예약 순간과 확인 여부는 그대로 보존합니다. 본문·ID·완료·생성 및 수정 시각도 유지합니다.

## 일회성·반복 알림

- 시각 한 번은 현재 분이면 즉시, 미래 분이면 오늘, 지난 분이면 다음 로컬 날짜에 예약합니다.
- 매일·요일 반복은 고정 24시간 덧셈 대신 로컬 달력으로 다음 회차를 계산합니다. DST에서 없는 시간은 JavaScript Date의 로컬 보정을 따르고 반복 시간대의 현재·미래 분은 현재 구간을 고려합니다.
- 본문만 바꾸면 예약·확인 상태를 유지합니다. 모드·시간·요일 변경은 재예약하고 완료·삭제·알림 해제는 취소합니다. 완료 취소는 설정된 일정으로 다시 활성화합니다. 고정된 일회성 `dueAt`이 이미 지났으면 즉시 도래 항목이 됩니다.
- 약 1초 간격·잠자기 복귀·재실행 때 미확인 도래 항목을 조회해 예약 시각·ID 순서로 하나씩 표시합니다. 드래그·놓기·메뉴 조작 동안 새 표시는 미룹니다.
- 닫기 요청은 먼저 확인을 저장합니다. 일회성은 `acknowledged: true`, 반복은 확인 시각보다 뒤의 다음 회차와 `acknowledged: false`를 저장합니다. 실패하면 현재 말풍선과 예약을 유지합니다.
- 반복 회차를 여러 번 놓쳐도 메모별 미확인 예약 하나만 복원합니다. 확인하면 현재보다 뒤로 진행하므로 누락된 과거 회차를 연달아 만들지 않습니다.
- 닫기 확인과 메모 완료는 별개입니다. 표시마다 고유 말풍선 ID를 사용해 이전 닫기 요청이 다음 알림을 닫지 못하게 합니다.
- 저장된 현재 예약 순간은 재실행·시간대 변경만으로 다시 정하지 않습니다. 반복의 다음 회차는 확인 시점의 로컬 달력으로 계산합니다.

우선순위는 실제 메모 알림 → 퇴근 전 요약 → AI 생성 상태·답변 → 수동 미리보기입니다. 숨긴 캐릭터는 알림 때 임시 표시되고 대기 항목을 닫으면 원래 숨김으로 돌아갑니다. 관리 패널을 열면 명시적 표시로 전환합니다. 알림 중에는 `notify` 포즈를 유지하되 드래그·놓기 포즈를 먼저 적용합니다.

## 자동 퇴근 전 요약

`WorkBriefingService`가 적용된 근무시간과 미완료 메모로 계산합니다. AI 실행이 필요하지 않습니다. 기본 설정은 `{ enabled: false, beforeMinutes: 30 }`이며 5~120분 전을 정수로 설정합니다. 관리 패널 저장과 대화 명령이 같은 서비스를 사용합니다.

출근 이후이며 퇴근 전 알림 구간이고 미완료 메모가 있을 때 개수와 최대 5개 제목을 표시합니다. 퇴근 시각 이후에 지난 요약을 새로 만들지 않습니다. 요약이 유효한 동안 남은 시간·목록을 갱신하고 유효하지 않게 되면 정리합니다. 메모 알림이 우선이며 입력 조작 중에는 표시를 미룹니다.

`briefing.json`은 `{ version: 1, settings: { enabled, beforeMinutes }, acknowledged: [...] }`입니다. 근무 출근일·출근시각·퇴근시각의 조합으로 회차를 식별하고 확인한 회차는 재실행해도 다시 표시하지 않습니다. 확인 기록은 최근 최대 400개입니다. 설정과 확인은 임시 파일·이름 변경으로 저장한 뒤 메모리에 반영합니다. 실패하면 성공으로 처리하지 않습니다. 이 파일은 메모·근무시간 파일과 분리합니다.

## AI 대화와 앱 명령

`ChatService`는 공통 `AgentProvider`를 사용하며 기본 어댑터는 `CodexProvider`입니다. Provider별 CLI 인자·실행 파일·JSONL은 어댑터 내부에만 둡니다. 다른 Agent로 바꾸는 커스터마이징은 [AI 연결 안내](agent-provider-guide.md)의 공통 계약과 요청 예제를 따릅니다.

대화 이력은 역할·상태·시각을 가진 메시지로 메모리에 보관합니다. 후속 질문에는 실제 이전 이력을 순서대로 전달합니다. 취소·실패한 질문은 그 상태로 남으며 성공 답변을 만들지 않습니다. 전체 제한에서는 이력을 몰래 잘라내지 않고 새 대화를 안내합니다. 창·말풍선을 닫아도 이력·초안·요청을 유지합니다. **새 대화**는 진행 요청·대기 말풍선·모호한 명령 대상 선택과 이력을 초기화하고 앱 종료도 대화를 지웁니다.

명령 모드의 Provider는 일반 답변 `{ kind: 'reply', text }` 또는 정확히 한 명령 `{ kind: 'command', command: { name, ...args } }`을 제안합니다. `AppCommandService`가 허용 목록·키·값을 검증하고 controller의 앱 포트로 `MemoService`·근무 저장·캐릭터·창·브리핑을 실행합니다. 파일 저장 성공 후 앱이 결과 문장을 만듭니다. 형식 오류·미지원 명령·잘못된 값은 데이터를 변경하지 않습니다.

대상 메모 검색이 여러 개면 후보를 제시하고 후속 번호로 선택합니다. 같은 전체 본문 후보가 여럿이면 번호를 다시 요구합니다. 후보의 ID와 내용·완료·일정·수정 상태를 대조하므로 선택 전에 변경된 항목에 오래된 요청을 적용하지 않습니다.

신뢰된 chat main frame만 연결 검사·질문·새 대화·대화 단축키 변경 IPC를 호출합니다. 취소는 chat·widget에서 요청 ID를 검사합니다. 직접 메모·근무·브리핑 변경 IPC는 panel에 한정하며 대화 명령은 별도의 검증된 main 서비스 경로를 사용합니다. 한 번에 한 연결 검사 또는 질문만 실행합니다. 취소·종료·새 대화 후 늦은 결과는 명령 실행·상태·말풍선을 바꾸지 못합니다.

질문 중에는 조용한 **응답 생성 중…** 말풍선을 표시합니다. 접기는 표시만 숨기고 취소는 요청을 종료합니다. 메모 알림·퇴근 전 요약이 먼저 표시되고 대기 AI 말풍선은 그 뒤에 표시합니다.

일반 대화에 메모·근무시간 파일 전체를 자동 제공하지 않습니다. 요청한 조회·요약·변경 결과는 사용자에게 보이는 답변이므로 이력에 남고 후속 질문에 전달됩니다. 현재 로컬 날짜·시각·요일은 명령 계획의 시각 기준으로만 제공합니다. 개발 지침·개인 설정은 대화 이력으로 취급하지 않습니다.

Codex는 앱 전용 지침으로 코딩 역할을 대체하고 프로젝트 안내·개인 설정·스킬 안내를 차단합니다. 도구·파일 권한을 늘리지 않으며 AI는 명령 제안만 수행합니다. 실행·인증·제한·교체 검증 항목은 [AI 연결 안내](agent-provider-guide.md)에 있습니다.
