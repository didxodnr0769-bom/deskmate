# 구조와 구현 범위

이 문서는 데스크톱 시제품의 코드 경계와 후속 기능의 연결 위치를 설명합니다. 구현된 기능은 소스와 검증 결과를 기준으로 판단하며, 아래의 후속 설계는 구현 완료를 의미하지 않습니다.

## 현재 프로세스 구조

```text
Electron main
  ├─ macOS 창·모니터·전역 단축키 관리
  ├─ 캐릭터 이동·드래그·표시 상태
  ├─ 근무시간 계산·저장
  ├─ 메모 검증·변경·저장, 일회성 알림 예약·확인 상태
  ├─ 단일 질문·답변 상태와 Provider 실행·취소
  └─ 허용된 IPC 처리
       ↕
preload: window.companion
       ↕
renderer
  ├─ Canvas 2D 캐릭터·HP·말풍선
  └─ React 근무·메모·대화 패널
```

`src/shared/contracts.ts`가 main과 renderer 사이의 상태·명령 형식을 정의합니다. `src/preload/index.ts`는 그중 앱에 필요한 기능만 `window.companion`으로 노출합니다. renderer가 Node.js나 Electron API를 직접 호출하지 않는 경계를 유지합니다.

| `src/main/desktop/controller.ts` | 네이티브 창, 전역 단축키, 모니터, 드래그와 자율 이동, IPC 수신 |

캐릭터의 동작 상태는 `idle`, `walking`, `dragged`, `dropping`, `notify`입니다. 사용자가 외형을 바꾸면 각 상태의 그림과 움직임도 함께 수정하되, 창 이동·클릭·패널 기능은 기존 앱 계약을 사용합니다.

창은 모니터 작업 영역 안에서 X·Y 방향으로 이동하고 양쪽 축의 경계에서 반사됩니다. 모니터 간 이동은 드래그로 수행합니다. 드래그를 놓으면 해당 위치를 유지하며, 창이 작업 영역을 벗어났을 때만 영역 안으로 조정합니다. 놓은 뒤 280ms의 `dropping` 상태는 캐릭터 포즈를 표현하는 구간입니다.

드래그와 자율 이동의 네이티브 위치 변경은 controller의 `moveWidget`을 거칩니다. `geometry.ts`의 `nativePosition`은 유한한 좌표를 반올림하고 int32 범위를 검사하며, Electron 정수 변환이 거절하는 `-0`을 `+0`으로 정규화합니다. `Math.round(-0.5)`도 `-0`이 되므로 반올림만으로는 충분하지 않습니다.

알림은 말풍선이 닫힐 때까지 유지합니다. 평상시에는 `notify` 상태이며 드래그·놓기 동안에는 해당 동작을 우선한 뒤 `notify`로 복귀합니다. 패널 열기나 잠자기 복귀만으로 알림 자세를 해제하지 않습니다. 점프 횟수·속도·높이와 점프가 끝난 뒤의 대기 포즈는 캐릭터 정의가 결정합니다.

main이 받는 클릭 영역은 `rect` 또는 `polygon` 형식입니다. 캐릭터를 바꿀 때 시각적 윤곽과 클릭 영역을 함께 조정해야 투명한 영역이 뒤쪽 앱의 클릭을 불필요하게 가로채지 않습니다.

## 현재 제공하는 범위

- 기본 돌멩이와 상태별 Canvas 애니메이션
- 캐릭터와 함께 이동하는 실제 퇴근 HP 게이지
- 작은 패널에서 출근일·출근시간·퇴근시간 적용, 자율 이동·단축키 조작
- 같은 패널의 메모 탭에서 추가·수정·완료·완료 취소·삭제와 선택적인 알림 시간 기록
- 캐릭터 드래그, 모니터 사이 드래그, 작업 영역 안의 X·Y 자율 이동
- 숨기기·다시 표시하기
- 알림 점프와 말풍선 미리보기
- 메모 시각의 일회성 무음 알림, 숨김 상태 임시 표시·복귀, 미확인 알림 복구와 확인한 알림의 중복 방지

미리보기와 실제 메모 알림을 구분합니다. Codex CLI의 단일 질문·답변 연결을 제공합니다. 반복 알림과 대화로 앱 데이터를 조작하는 기능은 구현하지 않았습니다.

## 근무시간 계산과 저장

패널의 편집 중인 입력과 적용된 근무시간을 구분합니다. 출근시간을 바꾸면 퇴근시간을 +9시간으로 채우고, 사용자가 퇴근시간을 다시 수정할 수 있습니다. 적용 요청은 main에서 다시 검증하며, 파일 저장에 성공한 뒤 상태를 갱신합니다.

- 날짜는 출근일의 로컬 날짜이며, 시각은 엄격한 `HH:mm` 형식입니다.
- 퇴근시간이 출근시간보다 이르면 다음날 퇴근입니다. 같은 시각은 거절합니다.
- 진행률은 1초마다 갱신합니다. 출근 전에는 0%, 근무 중에는 내림한 0~99%, 퇴근 시각부터 100%입니다.
- 남은 분은 퇴근까지의 시간을 올림 처리하고, 퇴근 이후에는 0분입니다.
- 저장된 출근일을 기준으로 계산하므로 자정이나 앱 재실행이 새 근무일을 만들지 않습니다.

근무시간은 Electron `app.getPath('userData')` 아래의 `worktime.json`에 `{ version: 1, schedule: { date, startTime, endTime } }` 형식으로 저장합니다. 임시 파일을 쓴 뒤 이름을 바꾸는 방식으로 교체하며, 불러올 때 버전과 날짜·시각을 검증합니다. 저장 파일이 손상됐으면 오류를 표시하고 다시 입력할 수 있게 합니다.

현재 재실행 후 복원하는 데이터는 적용한 근무시간, 메모와 알림 예약·확인 상태입니다. 캐릭터 위치·자율 이동·단축키는 실행 세션의 상태입니다.

## 메모와 저장

메모는 근무시간 계산이나 캐릭터 렌더링과 독립적인 `MemoService`가 관리합니다. main은 추가·수정·완료 변경·삭제 요청을 처리하고, renderer는 `window.companion`의 `addMemo`, `updateMemo`, `setMemoCompleted`, `deleteMemo`를 통해 요청합니다. 각 요청 결과는 성공 여부와 오류를 돌려주며, 메모 목록과 불러오기 오류는 공통 상태의 `memos`, `memoError`로 전달합니다.

- 메모의 본문과 선택적인 알림 시간을 편집합니다. 완료·완료 취소를 지원하며, 삭제 전 확인은 UI가 담당합니다.
- main이 ID와 생성·수정 시각을 생성합니다. 본문은 앞뒤 공백을 제거한 1~1,000자이며, 완료 항목을 포함해 최대 500개입니다.
- 패널은 기존 360×510 크기 안에 메모 탭을 제공합니다. 편집 중인 입력은 저장된 목록과 구분합니다.
- 날짜 없이 `time` 입력으로 시간만 선택합니다. `MemoDraft.reminderTime`은 엄격한 `HH:mm` 문자열 또는 `null`이며, 목록도 `15:00`처럼 시간만 표시합니다. 앱 내부에서 예약한 순간은 별도 `reminder.dueAt`으로 저장하며 사용자 날짜 입력은 추가하지 않습니다.
- 반복 알림은 없습니다. 메모를 완료하면 예약을 취소하며 항목은 보관합니다.

파일은 `app.getPath('userData')` 아래의 `memos.json`이며 다음 형식을 사용합니다.

```text
{ version: 3, memos: [{ id, text, reminderTime, completed, createdAt, updatedAt, reminder: null | { dueAt, acknowledged } }] }
```

`reminderTime`은 `HH:mm` 문자열 또는 `null`이고, `createdAt`과 `updatedAt`은 밀리초 단위 타임스탬프입니다. `reminder`는 main 내부 필드로 renderer의 `Memo`에는 노출하지 않습니다. 저장은 권한 `0600`의 임시 파일을 쓴 뒤 이름을 바꾸어 교체하며, 저장에 성공한 뒤 메모리 상태에 반영합니다.

불러올 때 파일 전체의 버전·각 항목의 형식·개수 제한·중복 ID를 검증합니다. 읽기 실패, 손상된 항목이나 미지원 버전이 있으면 원본 파일을 덮어쓰지 않고 메모 탭에 오류를 표시하며 메모 편집을 비활성화합니다. 일부 항목만 조용히 버리거나 빈 목록으로 덮어쓰지 않습니다. 근무시간 저장과 메모 저장은 별도 파일입니다.

이전 v1의 `reminderAt` ISO UTC 문자열은 읽는 Mac의 로컬 `HH:mm`으로 변환하고 날짜를 제거합니다. v1/v2의 ID·본문·완료·생성 및 수정 시각을 유지하며, 읽기만으로 파일을 교체하지 않습니다. 이전 버전에 예약 기능이 없었으므로 미완료·시간 지정 항목은 업그레이드 시 로컬 현재 시각에서 다음 시각으로 예약합니다. 첫 알림 초기화(`getDueReminders`) 또는 메모 변경 시 원본을 `memos.v1.backup.json` 또는 `memos.v2.backup.json`에 `wx`·권한 `0600`으로 백업한 후 v3를 저장합니다. 기존 백업은 보존합니다. 백업 또는 저장 실패 시 원본과 메모리 상태를 유지하며 알림을 전달하지 않습니다.

## 일회성 알림

- 시간 지정 시 오늘의 미래 분, 현재 분이면 즉시, 이미 지난 분이면 다음 로컬 날짜에 한 번 예약합니다. 날짜 계산은 고정 24시간 가산 대신 로컬 달력을 사용합니다. DST의 없는 시간은 JavaScript Date의 로컬 보정을 따르고, 반복되는 시간대의 현재·미래 분은 현재 구간을 유지합니다.
- 본문만 수정하면 예약과 확인 상태를 유지합니다. 시간 변경·해제 후 재지정·완료 취소는 재예약하고, 완료·삭제·시간 해제는 취소합니다.
- `MemoService.getDueReminders`는 미확인·도래 항목을 예약 시각과 ID 순으로 제공합니다. controller가 약 1초 간격 및 `onResume`에서 조회하며, 표시 중 알림을 덮어쓰지 않고 하나씩 전달합니다. 드래그·놓기 중 새 알림 표시는 조작 종료 후로 미룹니다.
- 말풍선을 닫으면 `acknowledgeReminder`로 확인 상태를 먼저 저장합니다. 실패하면 말풍선과 예약을 유지하고 오류를 표시합니다. 말풍선 표시마다 고유 ID를 부여하여 이전 말풍선의 지연된 닫기 요청이 다음 알림을 닫지 못하게 합니다. 닫기는 신뢰된 widget main frame의 IPC만 받습니다.
- 재실행 때 미확인·도래 항목을 복구합니다. 닫지 않은 알림은 다시 표시하고, 확인 상태가 저장된 알림은 다음날에도 반복하지 않습니다. 확인이 메모 완료를 뜻하지는 않습니다.
- `reminder.dueAt`은 예약한 순간을 고정하므로 재실행·시간대 변경에서 임의로 다시 계산하지 않습니다. 시스템 시계를 뒤로 돌려도 이미 표시 중인 알림은 유지합니다.

숨긴 캐릭터는 `temporaryAlert`로 잠시 나타나고 대기 알림을 모두 닫으면 이전 숨김으로 돌아갑니다. 사용자가 패널을 열면 명시적 표시로 전환합니다. 수동 미리보기는 예약 알림을 덮어쓰지 못하며, 예약 알림은 미리보기보다 우선합니다. 앱이 종료된 동안에는 스스로 알릴 수 없습니다.

근무시간·메모·예약 계산과 저장은 캐릭터 렌더러나 AI 응답과 분리돼 있습니다. 캐릭터 교체는 업무 데이터나 예약 상태에 영향을 주지 않습니다.

## AI 질문·답변

`ChatService`는 Provider 공통 계약을 사용하며, 기본 구현은 `CodexProvider`입니다. 실행 파일·CLI 인자·JSONL 출력은 Codex 어댑터에만 있습니다. 다른 Provider는 `DesktopController`의 `agentProvider` 옵션으로 주입할 수 있으며 사용자용 선택 UI는 아직 없습니다.

신뢰된 panel main frame만 연결 검사·질문·취소 IPC를 호출합니다. 연결 검사나 질문은 한 번에 하나만 실행합니다. 취소는 요청 ID를 확인하고, 취소·종료 이후 늦게 끝난 응답은 상태나 말풍선을 변경하지 못합니다. 질문·답변은 마지막 한 쌍만 메모리에 유지하며 메모·근무시간 저장과 분리합니다.

답변이 도착하면 패널을 유지하면서 캐릭터 말풍선에도 표시합니다. 예약 알림이 우선이며, 알림을 닫은 뒤 대기한 답변을 표시합니다. 드래그·놓기 중에는 답변 말풍선 표시를 미루고, 새 질문은 이전 답변 말풍선과 대기 답변을 제거합니다. 말풍선 닫기는 질문·답변을 지우지 않습니다.

구체적인 실행·인증·오류 처리와 남은 확장은 [AI 연결 안내](agent-provider-guide.md)를 참고하세요.
