# 첼시 보행 재검토

## 현재 판정: 자연스러운 전신 보행 미완료

현재 런타임 후보 `62028a7`은 실제 Linux Electron 검토에서 다리 접합부와 단일 몸통 정지·회전이 개선됐지만, 몸통·머리가 고정된 채 다리만 움직이는 인상 때문에 자연스러운 보행으로 승인되지 않았습니다. 자동 검사 통과와 별개로 첫 번째 요청은 미완료입니다.

후속 조사에서는 원본 첼시와 16개 위상의 네 발 접촉 안내도로 전신 연속 원화를 한 번 생성했습니다. 가까운 앞발이 대부분 앞으로 뻗고 네 발의 순서를 일관되게 연결하지 못해 품질 기준에서 중단했으며 앱에는 반영하지 않았습니다. 이 실패한 실험의 그림·영상은 현재 소스에 포함하지 않습니다. 완료하려면 일관된 전신 연속 원화 또는 목·견갑·흉곽·골반·다리까지 연속 변형할 수 있는 미술 데이터가 필요합니다. 같은 고정 몸통 리그의 폭·속도·프레임 수 조정만으로 완료했다고 설명하지 않습니다.

## 이전 구현을 거절한 이유

`6833cc3`의 16장 시트는 실제 고양이의 연속 촬영이나 관절 추적 자료가 아닙니다. 기존 첼시 시트를 참고해 이미지 생성 도구로 새 그림을 만든 뒤 다시 생성한 결과입니다. 서로 다른 픽셀·alpha 윤곽 32개라는 검사는 로딩 건전성만 확인했으며, 발 디딤·관절 순서나 자연스러움을 검증하지 못했습니다.

이전 제작 프롬프트는 16개 셀 안에서 앞발의 8단계를 두 번 반복하면서 반대 앞발을 8셀 뒤로 옮기도록 지시했습니다. 이는 의도한 좌우 교대와 맞지 않았고, 실제 그림에서도 앞발이 주로 앞으로 뻗고 잠깐 접힌 뒤 다시 뻗었습니다. 뒷발에도 일관된 지지→후방 이동→발 떼기→스윙이 없었습니다. 보폭 28px 역시 그림의 지지 발 이동량과 연결돼 있지 않았습니다.

로더가 각 셀을 외곽 경계의 중앙·가장 낮은 alpha 픽셀로 다시 정렬해 꼬리·머리 변화가 몸통 위치에 영향을 줄 수 있었습니다. 실제 Linux Electron 검토에서는 걷기에서 앉기로 바뀌기 직전에 오른쪽 캐릭터가 작아지는 문제도 관찰됐습니다. 해당 보행 시트는 현재 자산에서 제거하고 Git 이력에만 보존했습니다.

## 참고한 1차 연구

- [Day & Jayne, 2007, Journal of Experimental Biology](https://webcentral.uc.edu/eprof/media/attachment/eprofmediafile_74.pdf), DOI `10.1242/jeb.02703`: 실제 고양잇과 9종의 측면 보행을 분석했습니다. Fig. 2는 관절 위치, Table 2의 집고양이 자료는 앞발 약 62%, 뒷발 약 59% 지지 비율을 제공합니다.
- [Klishko et al., 2014, Journal of Neurophysiology](https://pmc.ncbi.nlm.nih.gov/articles/PMC4137248/), DOI `10.1152/jn.00663.2013`: 실제 고양이 발끝 궤적, 관절 모델과 스윙 초기·말기의 발 위치 안정성을 연구했습니다. Fig. 1~3의 발끝·관절 표현을 참고했습니다.
- [Abourachid et al., 2007, Journal of Experimental Biology](https://journals.biologists.com/jeb/article/210/2/366/17115/Experimental-study-of-coordination-patterns-during), DOI `10.1242/jeb.02632`: 개·고양이의 보행을 시간상 지지 구간과 공간상 발자국으로 나누어 비교합니다. 프레임 개수와 발 디딤 검사를 분리하는 근거로 참고했습니다.

본문은 정상 접근 가능한 연구 본문·색인으로 읽었습니다. CAPTCHA가 나온 PMC 문서는 우회하지 않았습니다. University of Cincinnati PDF의 셸 다운로드는 403으로 실패했으므로 로컬 PDF를 내려받아 재생·분석했다고 주장하지 않습니다. 연구의 이미지는 제품 자산으로 복사하지 않았습니다.

## 수정 후보의 표현

새 `chelsea-walk-rig.png`는 첼시의 배포 이미지를 참고해 생성한 몸통 2방향과 위·아래 다리·발 재료 6개입니다. 이것도 촬영 자료가 아닙니다. 이미지 생성 도구에 보행 위상을 맡기지 않고 `chelsea-gait.ts`가 발끝 궤적과 관절 위치를 정합니다. 털 재료와 관절 모델을 합성하므로 종전 시트를 그대로 재생하는 방식과 표현상 차이가 있으며, 외형·관절 연결의 만족도는 육안 검토가 필요합니다.

- RH→RF→LH→LF를 0·25·50·75%의 네 발 디딤으로 배치했습니다. 앞발 지지는 62%, 뒷발은 60%로 두었으며 최소 두 발이 지지합니다. 이 수치는 간소화한 일러스트 모델이며 특정 고양이의 실측 한 주기를 복원한 것은 아닙니다.
- 몸통·머리는 방향별 한 이미지를 공통 해부학적 기준점에 고정하고, 작은 어깨·골반 하중 이동만 더합니다. 자세마다 몸통 크기를 바꾸거나 경계 상자 중앙으로 다시 맞추지 않습니다.
- 앞다리는 뒤쪽으로 굽는 팔꿈치, 뒷다리는 앞쪽 무릎과 별도 발목 구간으로 구성했습니다. 지지하는 발의 밑면은 공통 지면선에 둡니다.
- 한 보폭은 56 논리 px입니다. 지지 구간의 발 상대 X가 몸의 실제 수평 전진량과 같은 크기로 뒤로 이동합니다. 스윙의 세계 좌표는 한 보폭을 부드럽게 전진하고 양 끝 속도가 0이어서 지지 구간과 이어집니다. 작은 수직 곡선으로 발을 듭니다.
- main은 기존 X/Y 이동을 유지하면서 별도의 `strideDistance`에 수평 이동량을 축적합니다. 첼시의 보행 상태는 native 창 이동 주기(약 30Hz)에 맞춰 전송하고 renderer는 이 거리만 사용합니다. 다른 캐릭터의 기존 거리·전송 간격은 유지합니다. 위치 반올림과 IPC 지연이 실제 화면에 미치는 영향은 별도 점검 대상입니다.
- 정지는 마지막 보행 자세에서 시작해 420ms 동안 작은 순차 디딤으로 발을 몸 아래에 모읍니다. 이후 `chelsea-turn.png`의 측면 서기→회전→정면 앉기 8개 자세를 560ms 동안 표시합니다. 시작은 같은 시트를 역순 재생합니다. 한 번에 불투명한 몸통 하나만 표시하며, 전체 고양이 두 장의 디졸브는 사용하지 않습니다. 왼쪽 전환은 같은 연속 자세를 반전합니다. 전환 시트는 전체에 같은 배율을 적용하고 지면 근처 흰 발의 중앙을 공통 기준점으로 잡아 꼬리의 외곽 변화가 위치를 끌지 않게 합니다. 이 미술 keypose도 AI 생성물이며 정확한 3D 관절 회전이나 생물학적 캡처라고 주장하지 않습니다.
- 클릭 윤곽은 각 미술 재료와 동일한 변환을 사용합니다. 추가 자산 실패 시 기존 8장 시트, 기본 시트도 실패하면 Canvas 외형으로 돌아갑니다. 동작 줄이기는 대표 정지 자세를 사용합니다.

## 실제 Linux 검토 뒤 외형·전환 수정

`5ea32bc`는 양방향 발 교대와 화면 이동이 보인다는 피드백을 받았지만 완료 판정은 거절됐습니다. 가는 각진 다리·작은 흰 발이 긴 털 몸통 아래에서 기계식 지지대처럼 보였고, 정지할 때 측면과 정면 두 몸통이 겹쳤습니다. 작은 기존 회전 자세로 축소되는 현상은 이 후보에서는 관찰되지 않았습니다. native 접지 오차는 화면 표본만으로 수치 검증하지 않았습니다.

`eb1ed4c` 수정은 몸통을 7px 낮추고 다리 뼈를 18.5/20.5px로 짧게 만들었습니다. 털 폭은 상부 앞/뒤 18/23px, 하부 12px, 발 12/13px로 늘렸습니다. 윗다리는 몸통 아래에, 가까운 아래 다리는 몸통 앞에 그리며 접합부를 겹쳐 둥근 부품이 외부에 붙거나 가는 뼈만 드러나는 모습을 줄였습니다. 먼 쪽 다리는 투명하게 만들지 않고 밝기만 낮춥니다. 보폭은 짧아진 다리에 맞게 72→56px, 발 들기는 앞 6.5/뒤 6px로 줄이고 기존 지지 발 위치 추적은 유지했습니다. 전체 디졸브는 제거하고 위의 단일 몸통 전환 시트를 추가했습니다. 보행은 연속 관절 자세이며 새로 손으로 그린 16장 시트라고 설명하지 않습니다.

실제 크기의 양방향 8위상 접촉 시트, 정지 전환 시트와 30fps 비교 녹화를 생성해 이미지의 연결·크기를 점검했습니다. 클라우드에서는 시간 표본을 검사했으며 native 실시간 재생의 자연스러움 승인은 별도입니다. 외형이 충분한지, 동작이 고양이답게 느껴지는지는 새 후보로 다시 native 검토해야 합니다.

## 분절 접합부에 대한 집중 수정

`eb1ed4c`의 실제 Linux 검토에서는 두꺼운 발과 양방향 교대, 단일 몸통 정지·회전, 축소 방지가 확인됐습니다. 하지만 겹친 뒷다리의 접합부와 별도 조립한 발·종아리, 고정 몸통 아래의 낮은 셔플 때문에 자연스러운 고양이 보행 승인은 받지 못했습니다.

집중 수정은 새 프레임·새 그림을 추가하지 않습니다. 개별 위·아래·발목 재료의 둥근 옅은 끝부분이 관절마다 중첩되던 그리기를 제거했습니다. 기존 회색 털의 연속 표면 하나를 어깨/골반→팔꿈치/무릎→발목의 부드러운 곡선에 입혀 다리당 한 털 외곽으로 연결합니다. 발목에서 발의 회색 윗부분이 겹치도록 기준점을 맞췄으며 별도의 뒷발목 조각은 제거했습니다. 가까운 다리의 상단은 몸통 털 아래로 숨기고, 아래쪽만 앞에 보입니다. 블러나 반투명 유령 이미지는 사용하지 않습니다. 클릭 윤곽도 같은 삼각형 변환으로 계산합니다. 몸통 크기·보폭·발의 지지/스윙 경로와 단일 몸통 시작·정지 자산은 유지합니다.

어깨·골반의 작은 수직 반응은 독립 사인파 대신 실제 지지 구간에서 부드럽게 증가·감소하는 하중 모양에 따릅니다. 앞·뒷발의 지지로 각 위치의 압축과 몸통 기울기를 함께 정하며 발밑 기준점은 바꾸지 않습니다. 이는 1도 미만의 일러스트 하중 표현으로, 실제 힘·근육·3D 보행을 복원한 것은 아닙니다. 같은 수평 이동 표본을 기다리는 동안에는 이미 그린 관절 표면을 재사용합니다.

이 재료에는 독립된 머리·목·견갑·골반·털 볼륨 및 가림 관계를 설계한 미술 데이터가 없습니다. 연속 털 표면은 경계를 줄이지만 고양이의 견갑 활주, 척추 유연성, 옆모습 깊이와 털 변형을 충실하게 재현할 수 없습니다. 실제 크기의 시간 표본으로 점검한 후보를 전달하며 자연스러움의 완성이라고 주장하지 않습니다. 새 native 검토에서도 조립 느낌이 남는다면 같은 재료의 폭·속도·프레임 수를 반복 조정하는 것으로 완료 처리하지 말고, 일관되게 제작한 전신 연속 원화나 해부학적 겹침을 갖춘 별도 2D 미술 리그가 필요합니다.

## 검증과 아직 필요한 판정

`tests/chelsea-gait.test.ts`는 네 발 위상, 지지 중 세계 X 고정, 스윙 경로·발 들기·끝점 연속성, 고정 뼈 길이, native 위치보다 앞서지 않는 거리 선택을 검사합니다. controller 통합 검사는 실제 이동 상태와 전송된 상태를 사용해 네 크기에서 지지 발의 수평 오차가 native 좌표 반올림 범위(1px 이내)에 있는지 확인합니다. 수직 자유 이동을 포함한 화면의 모든 깊이·지면을 물리적으로 재현하는 3D 모델은 아닙니다.

`scripts/verify-chelsea-gait.mjs`는 실제 재료 8개 로딩, 양방향 130개 보행 자세와 촘촘한 정지 전환의 픽셀 크기·발 위치·클릭 윤곽을 검사합니다. `GAIT_VIDEO=1`은 이전 `eb1ed4c`와 집중 수정 후보의 양방향 걷기·시작·정지 비교 영상을 만듭니다. 영상의 창 위치와 시간은 제어된 브라우저 환경이며 native Electron 검증과 구분합니다.

수학적 지지 조건과 자동 테스트 통과는 자연스러움의 증거로 대신 쓰지 않습니다. native Linux 앱에서 반복 보행·시작·정지·방향 전환을 보고 첼시의 외형과 고양이답게 보이는지 판정해야 합니다. macOS native 동작, 장시간 CPU·전력·메모리, 물리 입력·모니터 조건은 이번 클라우드 점검으로 입증되지 않습니다.
